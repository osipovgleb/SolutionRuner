# Right-triangle pipeline

[Project](../../../../../README.md) → [Grid-polygon pipeline](../README.md) → **Right-triangle pipeline**

This package implements the deterministic content rule for right-triangle
problems whose condition gives a supported trigonometric value and side. The shared
[`grid_polygon_pipeline.launcher`](../README.md) owns inventory, progress,
batching, checkpoints, isolated task failures, and the final Helpers stage.
This child package freezes and applies only problem transformations.

An ordinary shared-launcher invocation performs both phases in one process. Every
solution is selected only from the task's own condition: known `AC` plus a
request for `AB` uses division by cosine; known `AB` plus a request for `AC`
uses multiplication by cosine; every other side combination is blocked as an
error. The tangent-hypotenuse rule instead requires `tg A`, known `AC`, and
requested `AB`, then writes the approved tangent-definition and Pythagoras HTML.
The tangent-opposite-cathetus rule requires `tg A`, known `AC`, and requested
`BC`; its missing-solution HTML uses the single chain
`tg A = BC / AC iff BC = AC tg A = ...`. Any other condition is blocked before
writes. Repeated runs migrate only older solutions generated by this same rule.
When a task already has a substantive solution and its materialized answer
equals the rule's reduced computed answer, the content result is
`already_complete`; an `--apply` run sends that verified result to the shared
Helpers stage and marks its configured branches ready without rewriting content.
The universal rule first identifies the right angle and then assigns the
hypotenuse, opposite cathetus, and adjacent cathetus relative to the stated
acute angle. Its four function definitions and six ordered known/requested side
pairs cover 24 normalized calculations, including all 144 equivalent labeled
condition shapes across right angles `A`, `B`, and `C`. It writes only missing
solutions, using two direct rows or a third Pythagorean/identity row, and
preserves a substantive solution when the independently computed answer agrees.
The altitude-universal rule covers the registered source groups from `27265`
through `27432` that actually exist in the theme. It treats `CH` as the
altitude to hypotenuse `AB`, reasons exactly over `AB`, `AC`, `BC`, `AH`,
`BH`, `CH`, `sin A`, `cos A`, and `tg A`, and may combine definitions from
triangles `ABC`, `ACH`, and `BCH` with the Pythagorean theorem. The basic
identity converts sine and cosine only when the complementary function itself
is required to reach the requested quantity. A given trigonometric function is
otherwise kept throughout the shortest proof: its side coefficients are
completed by Pythagoras and the known side fixes their scale. Tangent plus a
hypotenuse is likewise shown by substituting the tangent ratio into Pythagoras,
never by a tangent identity. Given sine, cosine, and tangent values are rendered
as proportional side coefficients in the order value, coefficient ratio, side
ratio, and side assignments. Each similar triangle uses its own scale variable
(`x`, `y`, or `z`); a known side fixes that scale immediately, while Pythagoras
supplies only a genuinely missing third coefficient or resolves a known
hypotenuse.
Unsupported, underdetermined, or inconsistent conditions and any
materialized-answer mismatch are blocked before transformations; a verified
answer is never rewritten.
Four elementary rules extend the same manifest and Helpers workflow without
using the trigonometric solver. Group `27617` applies Pythagoras and the
right-triangle area formula; group `27618` solves the smaller leg from area and
an integer leg difference; group `27742` solves the sum/difference system for
the larger acute angle, including half-degree results; and group `27753` uses
the exact larger-to-smaller angle ratio. Each rule fails before writes when the
condition does not match its registered family, preserves a substantive
solution, and rewrites only an incorrect or absent answer.
The next elementary families register groups `27761`, `27765`, `27770–27775`,
and `27789–27791`. Forward and inverse rules cover the median from the right
angle, intersections involving the altitude, median, and bisector, the altitude
length `CH = AB sin A cos A`, and projections `AH = AB cos² A` and
`BH = AB sin² A`. Formula-aware condition text restores inline LaTeX at its
original location before parsing, including source layouts such as a bare
formula value followed by a visible degree sign or `AB=` followed by a visible
number. Their generated solutions preserve the geometric argument of the parent
task and make each implication explicit: equal segments first establish the
relevant isosceles triangle, bisectors and altitudes determine their named
angles, and only then does the calculation follow. The three metric families
likewise state both successive trigonometric relations before substitution.
Every rule validates its exact requested quantity and fails closed on another
construction.
The first task supplies
only the shared condition image asset. The launcher freezes the manifest and,
with the explicit `--apply` gate, immediately applies it in bounded batches.

```bash
solution-runner \
  --group 27239 \
  --confirm-catalog 41bc4d03-40cd-4407-8dea-df76e3f47ea8 \
  --max-workers 10 \
  --batch-size 10 \
  --batch-pause-seconds 0 \
  --apply
```

Omit `--apply` to prepare and inspect the frozen manifest without changing
source content. The run directory is created under
`var/grid-polygon/` and contains `prepared-manifest.json`, stage
results, `summary.json`, and the shared `internal.jsonl` event log. Resume the
content phase with the ordinary launcher's `--resume-solutions RUN_DIR` option.
