# Квадратные неравенства: группа 185

Каталог `fd733f80-43d2-4b4a-b903-2423796cbee5`, категория 13,
тема `760bb497-c0ac-4833-b37e-aea079eb9af0`, группа
`fa22c171-2a79-4914-809f-2147181bf88c`. Правило:
`quadratic-inequality-graph-choices`.

Образец подачи — решение задачи 333004. Каждый из четырёх вариантов
сохраняет собственный блок: исходное неравенство и разложение на множители;
затем рисунок отдельной строкой; затем
отдельная строка `x\in` с промежутком или объединением и пустая строка перед
следующим пунктом. Для `x²+c` с положительной константой число переносится
вправо; затем следует «ист.» / «ложь., т.к. x²≥0 всегда» и вывод через
`x\in\mathbb{R}` / `x\in\varnothing`, без рисунка. Числовой ответ выводится
платформой отдельно. Уже добавленные рисунки таких вариантов удаляются из
Normalized и transformations, сохраняя исходные изображения условий.

Переиспользованы `Interval`, `interval_latex`, точные числа, исходная ось,
стрелка и контур x из `inequality_system_svg.py`, цвет и шаг штриховки,
общий diagram gateway, frozen manifest и readback.
`render_quadratic_sign_chart_svg` показывает метод интервалов: отдельную дугу
над каждым промежутком и знаки `+`, `−`, `+` внутри дуг; синим под осью
штрихуются только промежутки, удовлетворяющие неравенству. Для двойного корня знаки
`+`, `+`, при отсутствии действительных корней — один знак `+`.
Корни передаются независимо от ответа. Рисунки метода интервалов имеют
прозрачный фон. Раннер систем неравенств не меняется.

Поддерживаются строгие и нестрогие монические квадратные неравенства с целыми
коэффициентами и целыми корнями либо отрицательным дискриминантом.
Неизвестная грамматика блокируется. Номер варианта вычисляется независимо
от сохранённого ответа: решение каждого варианта сравнивается со множеством,
визуально прочитанным с рисунка условия. Свидетельство фиксирует UUID задачи,
контрольную сумму условия, UUID и SHA256 SVG и точные границы множества.

Визуально проверены **все 91 задача группы**. Свидетельства сохранены в
`quadratic_inequality_choices_evidence.json`. Четыре варианта каждой задачи
дополнительно решены независимой символьной проверкой: все 364 результата
согласуются с рисунками и ответами раннера.

В 14 условиях повреждённая запись вида `x 2 −6x<0` восстанавливается
в inline LaTeX с сохранением порядка вариантов. Восстановление защищено
контрольными суммами исходного и итогового условия. Другие условия и
исходные картинки сохраняются. Полный dry-run от 29.10.2026 подготовил
91 задачу без ошибок: 364 рисунка, 15 отсутствующих ответов и 25 исправлений
неверных ответов. Исходный сохранённый ответ не используется для выбора
правильного варианта.

## Проверка после записи

Сервер добавляет к изображениям служебные атрибуты
`data-transformation-target-id` и канонизирует порядок HTML-атрибутов.
Planner сравнивает решения через общий `condition_fingerprint`, который
игнорирует только эти служебные метки, сохраняя проверку формул, текста,
рисунков и их идентификаторов. Регрессии моделируют такое поведение сервера
для всех 91 задач и проверяют обнаружение настоящего изменения формулы.

Первое применение 29.10.2026 сохранило контент всех задач, но прежнее
буквальное сравнение HTML ошибочно дало `content failed authoritative readback`
и пропустило Helpers. После исправления полный read-only прогон подтвердил
91 задачу без оставшихся изменений контента. Повторное применение переиспользует
сохранённые SVG и завершает пропущенный этап Helpers.

После исключения рисунков очевидных вариантов `position` оставшихся
ассетов задаётся индексом в итоговом `asset_keys`, а не номером варианта.
Например, для рисунков вариантов 2 и 4 позиции равны 0 и 1. Старые позиции
1 и 3 приводили к пропуску добавления ассета при replay и ошибке
`media does not resolve to a normalized asset key`.

Исправление проверено без сетевых записей реальными серверными
`materialize_problem_transformations` и `validate_normalized_content`:
старый план воспроизводит ошибки 38 задач; исправленный план валиден для
всех 91, а итоговые HTML и `asset_keys` совпадают с ожидаемыми. В локальном
gateway тестов также проверяется диапазон и порядок позиций ассетов.
