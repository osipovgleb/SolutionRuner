# «Вкус» решения: профиль близости к родителю

Этот документ задаёт единый шаблон, как писать решения так, чтобы они были
**достаточно подробными**, **не распылялись в развернутую болтовню** и при этом
по стилю оставались в духе родителя.

## 1) Базовый ориентир (родительский вкус)

При генерации дочернего решения исходить из родителя задачи. Если родитель
содержит метод `M`, порядок рассуждений и обозначения, в дочернем решении
сохранять:

- метод `M` как основной путь вывода;
- последовательность ключевых шагов родителя;
- терминологию, обозначения (`S`, `a`, `b`, `h` и т.д.);
- порядок рисунка и смысловые акценты в выводе.

Отступать от родителя только когда это объективно требуется данными дочерней
задачи (другие числа, другая геометрическая конфигурация, другая стратегия).

## 2) Какой уровень подробности считать нормой

Ниже — целевой уровень для большинства задач.

- 1–2 коротких вступительных фразы: что считаем и зачем это нужно.
- От формулы к формуле: 1 смысловой переход на строку, без прыжков через 2–3
  преобразования.
- Каждый подстановочный шаг выделить отдельно.
- Один блок проверки/сверки промежуточного значения (если он нужен).
- Ответ в конце не дублировать лишними словами.

Обычно это даёт 5–9 формульных строк на решение (включая финальную) и
2–4 текста абзаца с объяснениями.

## 3) Что значит «не максимально широко»

Запрещено:

1. Прятать 3+ несвязанных действия в одной формуле.
2. Дублировать очевидные учебные места (`по определению`, `по формуле`), если
   шаг тривиален на данном этапе.
3. Добавлять альтернативные методы, если в родителе их нет и это не
   необходимо по математике.
4. Переписывать все теоремы полностью (только нужную для текущего хода).

Разрешено:

- добавить второй метод только если по данным дочерней задачи он объективно
  короче/нагляднее и родителю есть аналогичный уровень строгости;
- оставить один дополнительный рисунок-иллюстрацию только в случае
  усложнения геометрии.

## 4) Каркас объяснения, который можно копировать

```text
1) Определить, какая формула/свойство подходит.
2) Подставить значения задачи.
3) Упростить дроби/степени/квадраты/деления на квадрат.
4) Найти промежуточный параметр, если нужно.
5) Получить итог и перейти к ответу.
```

В HTML это обычно реализуется как:

- 1 абзац-вступление;
- 1 абзац на каждое ключевое преобразование;
- в конце итоговая формула и ответ.

## 5) Рекомендуемая мапа к `solution_text_profile` (для профилей
в `profiles.py`)

- `triangle-three-exterior`, `quadrilateral-pick` и т.п. — используем уже
  реализованные типовые ветки без изменений.
- Для остальных задач берём «нейтральную» формулировку без лишних расширений:
  короткая, но не обрезанная.

Если нужен специальный вкус, задавать в `GroupProfile`
`solution_text_profile` новый ключ через явный профиль и поддерживать его в
соответствующей стратегии.

## 6) Критерий принятия (чек-лист)

Решение проходит, если по каждому шагу:

- порядок из родителя сохранён;
- есть 1–3 промежуточные формульные подстановки;
- отсутствует «пустая» проповедь без вычислений;
- итог однозначно приводит к ответу, без лишней широты текста.
