# Спецификация общего раннера тригонометрических уравнений

## Охват и регистрация

Один content-rule `trigonometric-table-value-affine-argument` обслуживает три
группы темы «Тригонометрические уравнения» каталога
`41bc4d03-40cd-4407-8dea-df76e3f47ea8`:

| Группа | Функция родителя | Source group UUID | Порядок в теме |
| --- | --- | --- | ---: |
| `26669` | `cos` | `8511fed3-8953-4f5e-8d12-e4225fa69e0f` | 0 |
| `77376` | `tg` | `289f583b-338c-4908-a9e3-49038435a10f` | 1 |
| `77377` | `sin` | `ab321f4f-3a38-4a97-a449-888902691eaf` | 2 |

Профиль не выбирает алгоритм по номеру группы: функция, табличное значение,
аффинный аргумент и требование к корню читаются из условия каждой задачи.

## Строгая граница языка

Раннер принимает только уравнение одного из видов:

```latex
\sin u = c, \qquad \cos u = c, \qquad \tg u = c,
```

где `u` — аффинное выражение с `x`, умноженное на рациональный коэффициент
`\pi`, а `c` — явное табличное значение из утверждённого набора функции.

До включения конкретного значения в реестр его SVG и тест-кейс должны быть
подготовлены. Любая неоднозначная формула, неутверждённое значение,
неразобранное требование к корню или отсутствие ассета блокирует только эту
задачу и ничего не записывает.

## Общее решение

- После таблицы сразу записывается равенство для аргумента из условия: строка
  вида `cos u = 1/2` или `sin u = ...` не дублируется.
- Для двух ветвей `sin` и `cos` используется совокупность из двух равенств с
  одним параметром `k`; после совокупности всегда указывается
  `k\in\mathbb Z`.
- Для `tg` и крайних значений `sin`/`cos` строится одно равенство с
  `k\in\mathbb Z`.

После общего решения `x` выделяется в отдельных видимых шагах и в точном
порядке, в котором операция действительно требуется:

1. убрать знаменатель домножением;
2. убрать `\pi` делением;
3. убрать свободный член сложением или вычитанием;
4. убрать коэффициент при `x` делением.

Преобразования трёх совокупностей записываются одной формулой в display-режиме,
разделённой `\iff`. У простого аргумента используется запись `\pi x`, а не
`\pi(x)`; скобки остаются у составного аргумента, например `\pi(x-7)`.

## Выбор требуемого корня

Перед таблицей отдельным блоком «Общий алгоритм» объясняется:

1. подставить `k=0` в каждое уравнение;
2. изменять `k` на единицу «вверх» или «вниз», пока корень не перейдёт через ноль;
3. выбрать ближайший к нулю корень нужного знака.

В таблице каждая строка показывает саму подстановку, например
`x=8+6\cdot(-2)=-4`. Конечное значение в подстановке и итоговый корень
записываются десятичной дробью с запятой, если она конечна: `-5{,}5`, а не
`-\frac{11}{2}`.

Для двух веток публикуется одна таблица с двумя группами столбцов. Промежуточная
строка шапки `k | x | k | x` не выводится: в первом
столбце каждой группы сразу указывается подстановка `k=0`, `k=-1` и так далее.

| Первый корень |  | Второй корень |  |
| --- | --- | --- | --- |
| `k=0` | фактически вычисленное значение | `k=0` | фактически вычисленное значение |

Для одной ветки (`tg` и крайние значения `sin`/`cos`) публикуются два столбца:
`k` и `x`. В шапке, ячейках и итоговой записи не используются обозначения
`x_1` и `x_2`: итог пишется в одном абзаце после пояснения, например
«Ближайший к нулю отрицательный корень: `x=-4`».

## SVG-ассеты

Карта `src/solution_runner/pipelines/equations/assets/trigonometry/source-assets.json`
содержит 25 активных SourceAsset источника «ЕГЭ МАТ ПРОФИЛЬ»:
`source_site_id = 4e79360f-d623-4d50-9e85-67858ac1bc85`.
Источник `7bed2492-5b8b-4c88-9be8-7d47916cd7c6` — «ЕГЭ МАТ БАЗА»;
его ассеты нельзя привязывать к задачам профильного каталога.
Для существующего рисунка применяется `replace_problem_asset` с точным
`transformation_target_id` и SourceAsset ID из карты. После замены сохранённое
решение должно ссылаться на `/assets/{source_asset_id}`. Отдельная конвертация
SourceAsset в другой идентификатор не требуется.

SVG не рисуются новым стилем во время решения. Статические ассеты создаются
один раз разбором и очисткой эталона:

- исходник: `https://lessons-helper.ru/assets/1462b2e7-aa83-4c31-a512-412f3391c401`;
- SHA-256 скачанного исходника:
  `74d00aab259ff8adf2e9e354648c227cb8c870477b51de60f241a26b6f2fc11e`.

Из эталона удаляются синий полукруг, прежние контуры/текстовые path-метки,
служебные clipPath/defs и несоответствующие линии. Единичные отметки ставятся
тегами `text` напротив соответствующих концов окружности, а не в случайной
позиции исходника. Исходный файл не содержит имени шрифта: все его буквы уже
переведены в контуры. Поэтому новые подписи используют доступный в контейнере
`Liberation Sans` с запасным `DejaVu Sans`, а не неподтверждённое имя шрифта.

Общее оформление сохраняет координатную окружность, чёрные оси и тонкие линии
эталона. Дополнительные построения голубые и пунктирные:

- `cos`: вертикальные линии через обе точки окружности с данным значением;
- `sin`: горизонтальные линии через обе точки окружности с данным значением;
- `tg`: радиус до точки окружности и пунктирное голубое продолжение до
  контрольного значения на касательной;
- на каждой схеме явно подписаны оси `sin`, `cos` и `tg` (для `tg` также
  сохраняются оси окружности);
- каждая точка пересечения подписана конкретным табличным углом (`π/6`,
  `5π/6`, `3π/2` и т. п.), а не абстрактным `α`.

Каждая поддержанная комбинация «функция + табличное значение» имеет отдельный
статический self-contained SVG, локальное превью и тест XML/геометрических
инвариантов. Для трёх зарегистрированных групп пакет содержит все 25
стандартных комбинаций: 9 для `cos`, 9 для `sin`, 7 для `tg`.
Раннер только прикрепляет уже подготовленный подходящий ассет; он не генерирует
новый SVG в ходе обработки задач.

## Режимы

Сначала выполняется preview одной задачи без `--apply`, затем проверяются
формулы, таблица значений `k`, выбор ответа и назначенный SVG. Только после
этого возможен `--apply`.
